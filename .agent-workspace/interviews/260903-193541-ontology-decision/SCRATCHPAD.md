# 인터뷰 메모 - 온톨로지 도입 판단

## 맥락

- 날짜: 2026-09-03
- 참고자료: 현재 대화의 마케팅 콘텐츠 택소노미 v0 제안
- 인터뷰 목표: 현재 택소노미에 온톨로지가 필요한지, 필요하다면 어느 시점과 범위에서 필요한지 판단한다.

## 주요 주제

- 택소노미만으로 해결하려는 실제 업무와 한계
- 값 사이 관계를 명시해야 할 필요성
- 향후 질의와 자동화 요구
- Threads에서 이미 성과가 검증된 포맷의 국가 간 복제
- 박주원, 박태윤을 포함한 Trace 팀 전체가 함께 쓰는 공통 언어
- Trace를 넘어 회사의 여러 제품에 재사용되는 전사 마케팅 체계
- Threads, X 등 채널에 게시할 수 있는 마케팅 사진과 글의 생성

## 핵심 인사이트

- 분류의 첫 사용처는 분석 자체가 아니라, 한 국가에서 검증된 Threads 포맷을 다른 국가에 쉽게 복제하는 것이다.
- AI는 분류 체계와 별개의 실행 주체로서 이 정보를 활용하게 된다.
- 개인용 분류가 아니라 팀 전체가 같은 포맷을 같은 의미로 재사용할 수 있어야 한다.
- 국가가 달라져도 유지되어야 할 대상으로 사용자는 현재 마케팅하려는 제품을 먼저 꼽았다.
- 시스템은 Trace 전용이 아니며, 회사 내 어떤 제품에도 적용할 수 있어야 한다.
- 훅, 서사, 시각 구성은 국가마다 잘 작동하는 방식이 달라서 그대로 유지될 수도 있고 교체될 수도 있다.
- 재사용 단위는 하나의 고정 포맷보다 제품, 시장, 훅, 서사, 시각 구성의 조합에 가깝다.
- 사용자가 질문을 설계해서 검색하는 도구가 아니라, 에이전트가 제품과 목표 조건을 바탕으로 먼저 성공 패턴을 찾아 제안하는 시스템이다.
- 에이전트의 최종 산출물은 분류표나 분석 보고서가 아니라 실제 게시 가능한 마케팅 사진과 글이다.
- 택소노미나 온톨로지는 최종 사용자 산출물이 아니라 콘텐츠 생성 결정을 지원하는 내부 지식 구조다.
- 팀원이 생성 결과와 함께 포맷 선택의 성공 게시물 근거를 볼 수 있는 것이 바람직하다.
- 최소 추적 관계는 성공 게시물, 선택된 포맷 요소, 생성 콘텐츠에 실제 반영된 요소의 연결이다.
- 인터뷰에서는 관계 모델 용어보다 "새 콘텐츠를 만들 때 참고하는 과거의 실제 성공 게시물"처럼 실제 작업을 먼저 설명해야 한다.
- 과거 성공 게시물을 고를 때 가장 먼저 맞아야 하는 조건은 목표 국가다.
- 기본 선정 순서는 목표 국가로 후보를 제한한 뒤, 그 안에서 제품과 콘텐츠 적합성을 판단하는 방향이다.
- 채널마다 소비 방식과 성공 조건이 다르므로, 같은 국가라도 다른 채널의 성공 포맷을 그대로 근거로 사용할 수 없다.
- 검증된 포맷의 기본 적용 범위는 국가와 채널의 조합이다.
- 같은 국가와 채널의 성공 게시물은 제품이 달라도 참고할 수 있다.
- 다만 제품이나 고객 문제가 비슷한 게시물에 더 높은 우선순위를 둬야 한다.
- 국가와 채널은 필수 필터이고 제품 및 고객 문제 유사성은 가중치에 가깝다.
- 제품과 고객 문제의 유사성은 에이전트가 실행할 때마다 제품 설명과 게시물을 읽고 판단해도 된다.
- 유사성 관계를 사람이 사전에 정의하고 지속적으로 관리할 필요는 현재 확인되지 않았다.
- 현재 고정 구조가 필요한 것은 국가, 채널, 포맷 분류, 성과 근거와 출처다.

## 제약사항 및 경계

- 성과 예측, RAG, 온톨로지는 현재 초기 범위에서 제외한 상태다.
- 인터뷰를 통해 온톨로지를 계속 제외할지 재검토한다.

## 결정사항

- 첫 적용 채널은 Threads다.
- 택소노미는 Trace 팀 전체가 사용할 수 있는 형태여야 한다.
- 장기 사용 범위는 Trace 팀을 넘어 회사 전체다.
- 특정 국가의 성공 포맷을 다른 국가에 그대로 복사하는 것만을 목표로 하지 않는다.
- 사용자가 대표 분석 질문을 먼저 던지는 흐름을 기본 UX로 삼지 않는다.
- 초기 산출 채널에는 Threads와 X가 포함된다.
- 생성 대상에는 텍스트와 이미지가 모두 포함된다.
- 성공 게시물 추천의 최우선 필터는 국가다.
- 성공 근거는 목표 국가와 목표 채널이 모두 일치해야 한다.
- 다른 제품의 성공 게시물을 후보에서 완전히 제외하지 않는다.
- 제품·고객 문제 유사성은 사전 정의된 관계가 아니라 에이전트의 실행 시점 판단에 맡긴다.

## 긴장관계 및 트레이드오프

- 단순하고 운영 가능한 v0와 관계를 풍부하게 표현하는 모델 사이의 균형
- 검증된 포맷의 핵심을 보존하는 것과 국가별 현지화를 허용하는 것 사이의 경계
- 사람이 이해하는 공통 언어와 AI가 재사용할 수 있는 구조화된 명세 사이의 균형
- 원본 게시물의 외형을 복제하는 것과 성공 원리를 현재 제품에 맞게 번역하는 것 사이의 차이
- 전사 공통 개념을 유지하면서 국가별 성공 패턴의 차이를 표현해야 한다.
- 에이전트의 능동적 추천과 팀원이 추천 근거를 이해하고 검토할 수 있는 설명 가능성 사이의 균형
- 단순한 태그 필터링과 추천 근거의 관계·출처를 명시적으로 추적하는 구조 사이의 복잡도 차이
- 국가별 일반화와 채널별 특수성을 동시에 다뤄야 한다.
- 폭넓은 성공 사례 탐색과 유사 제품·고객 문제에 대한 집중 사이의 균형
- 매번의 유연한 의미 판단을 허용하면서 추천 결과의 근거는 재현 가능하게 남겨야 한다.

## 잠정 결론

- 지금 온톨로지를 도입하지 않는다.
- 국가와 채널을 필수 적용 범위로 고정한다.
- 게시물은 공통 택소노미로 훅, 서사, 메시지 관점, 시각 구성 등을 분류한다.
- 에이전트는 같은 국가·채널의 모든 성공 사례를 살피되 제품·고객 문제 유사성을 실행 시점에 판단해 우선순위를 조정한다.
- 생성 결과에는 참고한 실제 성공 게시물과 어떤 포맷 요소를 반영했는지 근거를 남긴다.
- 향후 사람이 제품·문제·고객·기능 관계를 반복해서 관리해야 하거나 다단계 관계 질의가 실제 요구로 나타날 때 온톨로지를 재검토한다.
