# 인터뷰 메모 - 마케팅 지식 구조

## 맥락
- 날짜: 2026-09-04
- 참고자료: 사용자가 제공한 "완성형 트레이스 마케팅 에이전트" 전체 구조와 현재 taxonomy 초안

## 주요 주제
- Slack에서는 한 명의 팀원으로 보이지만 내부 전문 모듈이 공용 마케팅 기억을 함께 사용한다.
- taxonomy와 LLM wiki를 대체 관계로 볼지, 서로 다른 계층으로 조합할지가 핵심이다.
- 현재 taxonomy 초안은 게시물을 일곱 차원으로 분류하고, 분류 공백을 AI가 제안하되 사람이 승인하는 구조다.
- LLM wiki는 정답 ID를 정의하는 곳이 아니라 에이전트가 판단할 때 읽는 서술형 근거 저장소로 구분한다.

## 핵심 인사이트
- taxonomy 초안은 검색 증강, 성과 예측, ontology reasoning을 명시적으로 범위 밖에 둔다.
- 따라서 taxonomy만으로 제품 사실, 시장 맥락, 과거 의사결정, 캠페인 서사를 모두 보존할 수는 없다.
- 반대로 자유형 문서만으로는 Analytics, Strategy, QA가 같은 ID와 기준으로 비교하기 어렵다.
- 사용자가 가장 먼저 막으려는 실패는 같은 콘텐츠를 매번 다르게 분류해 성과 비교와 학습이 흐트러지는 것이다.
- taxonomy는 비교 가능한 공용 언어를 제공하고, wiki는 왜 그런 분류·전략·결정이 나왔는지 설명하는 근거를 제공한다.
- 성과 수치와 게시 상태 같은 운영 사실은 wiki 문장보다 구조화된 데이터 저장소가 소유해야 한다.

## 제약사항 및 경계
- 외부에는 하나의 Slack 팀원으로 보여야 한다.
- 전문 모듈은 같은 공용 기억을 사용해야 한다.
- taxonomy 변경은 AI가 제안할 수 있지만 활성화는 사람 승인과 버전 기록을 거쳐야 한다.
- 현재 taxonomy 파일과 기존 작업트리 변경은 이번 인터뷰에서 수정하지 않는다.

## 결정사항
- 1차 기반은 taxonomy다. LLM wiki는 분류 일관성 문제가 해결된 뒤 근거와 서사를 보강하는 별도 계층으로 검토한다.
- LLM wiki를 taxonomy의 원본이나 성과 데이터베이스로 사용하지 않는다.

## 긴장관계 및 트레이드오프
- 자유로운 맥락 보존과 유연한 검색 대 일관된 분류와 집계 가능성
- LLM이 스스로 확장하는 속도 대 사람이 통제하는 공용 기준의 안정성
- 하나의 기억처럼 보이는 사용자 경험 대 내부 저장 계층의 명시적 분리
