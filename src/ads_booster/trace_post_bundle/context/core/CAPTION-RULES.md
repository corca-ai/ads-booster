# 캡션·일정 생성 규칙 (CAPTION-RULES)

> 이 문서는 IMAGE-RULES의 짝이다. 캡션은 **컨셉 수준**이고, 검증된 뼈대에 국가 값을 끼운다. 창작하지 않는다.
> 옛 규칙(`demo-kit/upload/CAPTION-RULES.md`, PRINCIPLES-\*·VOICE-KR·ELEMENTS-\*)은 참고 계층이며 상시 주입에서 뺐다 — 근거: 옛 로드 규칙 그대로 돌린 run-01 드라이런이 문서 간 충돌을 KR 6항목·JP 16행으로 보고했다 (`output/caption-dry/run-01/*/defects.md` §1).

## 0. 파이프라인 위치

```
컨셉 카드 (머리말 + 생활 프로필)
   ↓
[1] 캡션·일정 생성   Codex. 이 문서 §2~§5 → package.md (기본 일정은 한국어, 빈칸 포함)
[2] 국가별 렌더링    같은 생성 실행에서 카드 local 치환·번역 → localization.json
                    build_input.py가 검증·input.md 조립. 계절 교체 ≤2는 향후 지원, 현재 0
   ↓
IMAGE-RULES §0-1  대표 국가 text.png → final.png → 다른 국가 글자 교체 → 국가별 scene.png
```

컨셉 하나가 이미지 컨셉·모티프·씬 구도를 국가끼리 공유한다. 국가별로 다른 것은 **캡션의 현지화 슬롯(§2)과 잠금화면에 적히는 글자**뿐이다.

## 1. 산출물 — `package.md` 형식 (조립 스크립트가 읽는 계약)

캡션 단독 드라이런은 아래 YAML 블록 + 표를 쓴다. 통합 생성은 POST-RUN §3의 package.json이 정본이며 build_input.py가 package.md를 만든다. 두 형식을 따로 작성하지 않는다.

```yaml
concept: 귀여움
device_date: 2026-09-14        # 화면 기준일. run.json 지정값, 미지정 시 실행 지역의 오늘. 월요일일 필요 없음
device_time: "7:32"            # 카드의 생활 리듬에서 도출. 예시값 복사 금지
week: 2026-09-14 ~ 2026-09-20  # 월~일

captions:                      # 국가별 × 뼈대별
  kr:
    - skeleton: meme           # meme / recommend / discovery
      text: |
        (원문. 줄바꿈 유지)
      reply_link: "(2/2 답글 문구)"
  jp: [...]
  tw: [...]

localization: {}               # 국가별 치환 결과. 스크립트 출력이므로 [1]에서는 비운다
```

`schedule` — 기본 목표 18~22행. 기간 근거 부족 시 §4-1 총량 예외를 적용한다. 표로 쓴다.

| 제목 | 날짜 | 며칠 | 시각 | 종류 | 색 그룹 |
|---|---|---|---|---|---|
| 한국어. 빈칸은 `{동네}` `{카페}` `{팝업}` `{의원}` | 9/14 월 | 1 이상 | `HH:MM` 또는 종일 | 리듬 / 사건 / 기간 | 번호 |

`todos` — 8~12개. 날짜도 시각도 없다.

### 카드 계약 — 이 문서가 읽는 컨셉 카드의 머리말 칸

카드 파일은 별도로 만든다. 여기엔 계약만 적는다.

```
concept, motifs[], places[]
accounts.{kr|jp|tw}:
  handle, opener, meme_opener, recommend_middle, effect, reply_link, tutorial,
  local{ neighborhoods[], cafe, popup, clinic_word, seasonal[{date, name}] }
```

본문은 두 줄이면 된다 — **생활 리듬 1줄**(기상·출근·퇴근·취침), **관심사 1줄**.

### 형식 규칙

- **기본 3행.** 4행째 감정 꼬리는 선택이다.
- **조건절 오프너 금지.** "너도 자주 까먹는다면" 형은 TW에서 23·7이었다 (`如果你也很容易忘東忘西` 23, `如果你也常常忘記事情` 7).
- 이모지는 **행 끝에 0~1개, 캡션 전체에 1~2개.**
- **앱 이름을 본문에 쓰지 않는다.** 가리킬 때는 "이거".
- **현지화 범위는 `opener` · `meme_opener` · `recommend_middle` · `effect` · 이모지다.** 구조·행 수·링크 위치는 국가 불문 같다.

### recommend 고정 문장 조립

통합 생성은 카드의 `opener` / `recommend_middle` / `effect`를 순서대로 3행으로 쓴다. 이모지는 기존 §2 범위 안에서 행 끝에 붙인다. 둘째 줄을 실행자가 다시 번역하지 않는다. JP·TW의 둘째 줄은 각각 실측 원문을 유지하므로 단어가 아니라 세 행의 역할이 공통 구조다. KR 둘째 줄은 번역 초안이며 실측 성공으로 표기하지 않는다. 필드가 없으면 문구를 지어내지 말고 캡션 준비 공백으로 보고한다.
밈·발견담의 자동 조립까지 이 필드를 일반화하지 않는다. 해당 뼈대 문구/사용 조건은 스킬 선택 정책에서 별도로 확인한다.

## 4. 주간 일정과 할일

옛 `demo-kit/upload/CAPTION-RULES.md` §3~§4를 이식했다. 바뀐 곳은 굵게 표시했다.

### 4-1. 주간 일정 — 기본 목표 18~22행, 기간 비강제 우선

잠금화면이 보여주는 것은 하루가 아니라 **한 주**다.

| 축 | 개수 | 무엇 |
|---|---|---|
| 리듬 | 7~9 | 매주 같은 요일에 오는 것. 출근·수업·운동·정기 모임 |
| 사건 | 6~8 | 이번 주에만 있는 것. 예약·발표·약속·발매일 |
| 기간 | **0~4** | 2~3일짜리 띠. **카드의 관심사에 실재할 때만 쓴다** |

- **총량보다 기간 비강제가 우선한다.** 리듬 7~9·사건 6~8·기간 0~4의 축 범위를 먼저 지킨다. 카드에 기간 근거가 없어 합계가 18 미만이면 해당 합계를 허용하고 `schedule_exception`에 이유를 남긴다. 이는 새 성과 가설이 아니라 기존 기간 비강제와 수량 규칙의 충돌 해소다(통합 run-01, 2026-09-10). 예: 기간 0이면 합계 13~17. 총량을 채우려고 기간·리듬·사건을 억지로 늘리지 않는다.
- **기간을 억지로 채우지 않는다.** run-01에서 기간 3~4개 의무가 양쪽 국가 모두에서 억지 창작을 낳았다 (JP defects §2-5: "여행·출장·연수·전시 이력이 전무하다").
- **출근은 주 1행이다.** run-01 KR이 "일은 많아야 하나"를 종류로 읽어 평일 5행으로 펼쳤다 (KR defects §2). 행으로 읽는다.
- **제목 길이는 템플릿이 정한다.** 주간 띠(T3)에 들어가는 항목은 4~8자, 리스트(T2)는 제한 없음 — 말줄임은 렌더의 일이다 (IMAGE-RULES §1-ⓑ). 기본 일정은 제한 없이 쓰고, 조립 단계가 템플릿에 따라 띠용 짧은 제목을 요구한다.
- **시각은 3~5개에만 붙인다.** 나머지는 종일. 도달이 컸던 화면은 대부분 종일이었다.
- **하루에 몰지 마라.** 어떤 날은 4~5개, 어떤 날은 1개. 몰린 날에 `+3`이 뜨고 그게 화면을 살아 있게 만든다. 고르게 나누면 달력이 아니라 격자로 보인다.
- **색은 4~5그룹.** 성격이 같은 것끼리 같은 그룹 — 일은 한 그룹, 사람은 한 그룹, 운동은 한 그룹. 색 이름이 아니라 그룹 번호로 쓴다. 실제 색은 템플릿 슬롯이 갖고 있다 (IMAGE-RULES §1-ⓒ).
- 직무 작업을 늘어놓지 마라. 일은 "출근" 정도의 덩어리로만 쓴다.
  - 나쁜 예: "PR 리뷰", "월말 결산 마감 처리", "3분기 실적 자료 취합"
  - 좋은 예: "네일", "미피 굿즈 발매", "엄마 생신"
- "회의", "운동", "공부", "약속" 같은 범용 항목은 쓰지 않는다.

### 4-2. 고유명사 — 빈칸 4종 (교체된 규칙)

옛 규칙은 "고유명사·장소가 드러나야 한다"였다. 컨셉 하나를 여러 국가로 렌더링하는 지금은 국가에 묶인 이름이 그대로 번역될 수 없다. 그래서 **국가 종속 지명·매장·팀명을 쓰지 않고 빈칸으로 둔다.**

| 빈칸 | 채우는 곳 |
|---|---|
| `{동네}` | 카드 `local.neighborhoods[]` 순환 |
| `{카페}` | 카드 `local.cafe` |
| `{팝업}` | 카드 `local.popup` |
| `{의원}` | 카드 `local.clinic_word` |

`{의원}`은 진료과 이름 전체다. `{의원} 방문`처럼 쓰고 `{의원} 피부과`처럼 같은 뜻을 중복하지 않는다.

허용 — 빈칸 없이 그대로 쓴다:
- 활동명 (필라테스·네일·브런치·미용실)
- 글로벌 브랜드·캐릭터 (키티·미피·스타벅스·무인양품)
- 관계 (엄마 생신·친구 결혼식)

**컨셉 자체가 국가에 묶이면**(팬·스포츠 등) 그 카드는 해당 국가 블록만 갖고, 빈칸 없이 실명으로 쓴다.

### 4-3. 현지화 허용 범위

| 국가별 렌더링에서 바꿔도 되는 것 | 바꾸면 안 되는 것 |
|---|---|
| 빈칸 채우기 | 항목 개수 |
| 번역 | 요일 배치 |
| 날짜 표기 | 색 그룹 |
| 카드 `seasonal`이 그 주에 걸리면 사건 **≤2건** 교체 | 시각 |
| | 기간 길이 |

### 4-4. 일정은 곧 카피다

이미지 안에 40줄 가까운 텍스트가 들어간다. 사람들은 남의 잠금화면을 **읽는다.** 도달 209만을 낸 화면의 일정은 이랬다 — "기상 10:40 · 브런치 · 집 청소 · 카페 · 헤드폰 알아보기". 그 목록이 **어떤 사람인지를 보여준다.** 개수와 색만 맞추지 말고 그 사람의 하루가 읽히게 쓴다.

**캡션과 일정을 맞추는 규칙은 없앴다.** 캡션이 컨셉 수준이라 화면에서 찾아야 할 장면을 요구하지 않는다.

### 4-5. 할일 — 8~12개

날짜도 시각도 없는 **잡무**다. 일정이 아니다. 집세 내기 · 치과 예약 · 보험 갱신 · 택배 부치기 · 카드값 확인.

**여기서는 제목이 길어도 된다.** 목록 칸에 세로로 그려지기 때문이다. 도달이 가장 컸던 화면에는 "번개장터 팔린 옷 택배 접수" 같은 항목이 있었다. 주간 띠의 제목이 짧아야 하는 것과 **제약이 반대**다. 빈칸은 여기서도 쓸 수 있다.

## 5. 금지선

- 앱 이름·링크를 본문에 쓰지 않는다 (링크는 2/2 답글).
- **시연 동사 금지** — "만들어봤어", "세팅해봤어", "올려봤어". 연출임을 글 안에서 드러내거나 암시하지 않는다.
- **메이커 화법·제품 용어 금지** — 만들었다, 출시했다, 업데이트했다 / 배포, PR, 커밋, 리팩터링, staging, API, 스프린트, 온보딩.
- 조건절 오프너 금지 (§2 형식 규칙).
- 기능 설명 금지. 기능은 §3 튜토리얼 답글의 몫이다.
- 면책성 괄호 문구 금지 — "(개인 경험입니다)", "(데모입니다)".
- `FACTS.md` §2의 앵커 밖 동작이나 요금제를 서술하지 않는다.

**화자는 창작 컨셉 화자다. 글 안에서 정체를 공개하지 않는다.** `context/README.md` §9의 화자 2원칙과 `PRINCIPLES-*`의 메이커 1인칭 문장은 이 결정과 양립하지 않는다 — 폐기 대상으로 §7에 올려둔다.
