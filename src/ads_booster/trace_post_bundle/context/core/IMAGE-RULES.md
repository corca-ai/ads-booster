# 이미지 생성 규칙 (IMAGE-RULES)

> 캡션 파이프라인이 캡션·일정 데이터를 뽑듯, 이 문서는 그 데이터로 **잠금화면 이미지 주문서와 프롬프트를 에이전트가 쓰게 하는 지시문**이다.
> 규칙은 프롬프트에 넣지 않는다. 제약은 세 곳에 산다 — **템플릿 안**(레이아웃·크롬·폰트·막대 위치·**막대 색**, 그림으로 존재), **주문서 생성 단계**(형식·개수·정합·슬롯 배정, 이 문서), **검수**(사후 확인). 단일 국가 프롬프트는 A·B·C, 국가별 재사용 편집은 L이다 (§4).

## 0. 단일 국가 파이프라인 — 이미지 모델 호출 3번

```
입력 (주간 일정 · 할일 · 페르소나 · 기기 날짜 · 컨셉 · 모티프)  +  템플릿 명세 (context/templates/T*/spec.md)
        ↓
[1] 주문서 생성     텍스트 LLM. §1~§3 → 메타 / 화면 블록 / 슬롯 배정 / 계산 근거
[2] 텍스트 교체     이미지 모델(편집). 입력: template.png(흰 배경) + §4-A → text.png
    검수 A          §5 A 항목. 반려면 위반 문장을 A 뒤에 덧붙여 1회 재시도 → text-v2.png
[3] 배경 채우기     이미지 모델(편집). 입력: text.png + §4-B → final.png
    검수 B          §5 전체. 반려면 text.png에서 1회 재시도 → final-v2.png
[4] 씬 생성         이미지 모델(생성, final.png 레퍼런스). §4-C → scene.png
    검수 C          §5-C 10항목. 반려면 1회 재시도 → scene-2.png
        ↓
   저장 + 기록 (§6)   산출물 = 잠금화면(final) + 씬(scene). 카루셀 컷2·3은 final의 크롭 — 생성 불필요 (보류 항목)
```

**왜 이 순서인가 (v0.3에서 뒤집음):** 텍스트는 흰 배경에서 가장 정확하다. 배경은 **컴포넌트가 있는 화면 위에 여백을 채우는 편집**이어야 시계 옆·모서리·행간에 모티프가 들어간다 — 화면을 모른 채 따로 그린 배경(v0.2 `bg.png`)은 상단이 비고 붙여넣기 티가 났다. 배경 패스가 텍스트를 보존함은 2026-09-07 키티 사례로 확인됐고, 그래도 검수 B가 텍스트를 다시 대조한다.

### 0-1. 공통 원본을 쓰는 국가별 파이프라인 (run-02 사용자 육안 승인)

2026-09-10 사용자 평가: run-02 결과는 육안으로 바로 사용 가능한 수준. 이 방식은 현행 경로로 채택하되 한 원본·혼합 실행 모델의 결과이며 성공률·픽셀 동일성 검증은 아니다.

통합 실행 계약은 `context/POST-RUN.md`다. 이 절은 다국가 실행에서 §8의 국가별 A→B→C 반복보다 우선한다.

1. 대표 KR: T2 흰 템플릿 → A 텍스트 교체 → B 배경 채우기. 새 원본을 만든다.
2. JP·TW: 각각 **같은 KR 최종 원본** + §4-L로 화면 글자만 교체한다. 국가끼리 편집 결과를 이어 쓰지 않는다. B를 다시 실행하지 않는다.
3. 각 국가 final → C 씬. 완성된 C 프롬프트 문자열을 한 번만 정해 그대로 재사용한다. 참조 이미지만 국가별로 바꾼다.
4. 손·네일·소품의 작은 생성 차이는 허용한다. 잠금화면 배경·캐릭터·장식·레이아웃은 보존 대상이다.

3국 기준 이미지 호출 7회(A·B 2 + L 2 + C 3), 재시도 제외. A→B는 순차, 두 L은 독립이다. 이번 첫 실험은 원인 추적을 위해 국가별 결과를 확인하며 실행한다.

대표 B와 두 L을 검수한 뒤 씬으로 진행한다. 원본에 명백한 글자 오류가 있거나 L의 글자·디자인 보존이 재시도 후에도 반려되면 해당 실패를 숨기지 말고 씬 이전에 중단한다. A의 기존 기하 검수 실패만으로 B를 생략하지 않는 규칙은 유지한다. 게시 적합 여부와 실험 계속 가능 여부를 별도로 기록한다.

입력의 `concept_card`가 옛 `persona`를 대체한다. 시계는 package의 `device_time`을 그대로 사용한다. 씬 토큰 3개는 카드의 관심사와 §3-2의 허용 소재에서 한 번 도출해 공통 메타에 고정한다. 상세 인물 서사를 새로 요구하지 않는다.

## 1. 주문서 — 세 부분

**원칙: 템플릿은 언어 중립이다.** 주문서가 라벨·날짜 표기·구분선까지 대상 언어로 전부 담으면 템플릿이 일본어라도 상관없다. 국가별 템플릿을 미리 만들지 않는다.

### ⓐ 메타 — 프롬프트에 들어가지 않는다
```yaml
template: T2
language: ko
device_date: 2026-09-08          # 실제 달력. 요일은 계산한다 — 지어내지 않는다
date_line: "9월 8일 화요일"        # iOS 날짜 표기 (§2-5)
clock: "<h:mm>"                  # 앞자리 0 없음, AM/PM 없음. 페르소나 생활 리듬(기상·출근·취침)에서 — 예시값 복사 금지
concept: 귀여움                   # §3 컨셉 팩 행
motif: 헬로키티                   # 배경 모티프. 캐릭터명 허용 (팀 결정 2026-09-07)
style:                           # 컨셉 팩에서 도출. 팩이 비어 있으면 "시스템 기본 / 보통 / [열린 칸]"
  font: 손글씨·둥근체 느낌
  clock_weight: 굵게                # 시계는 글꼴의 영향을 받지 않는다 — iOS 기본 글꼴에 굵기·색만 (2026-09-08 피드백)
  clock_color: 모티프 포인트색 (키티 = 빨강·분홍 계열)
  text_tone: 짙게
  motif_style: 또렷한 외곽선과 채도 높은 평면 채색(스티커 일러스트 느낌)
scene:                           # §3-2 씬 팩에서 도출. 요일·일정 정합은 하지 않는다 (2026-09-08 결정 — 아무도 확인하지 않는 디테일에 비용을 쓰지 않는다)
  place: 카페 나무 테이블          # 장소 변주 목록에서 런마다 하나씩 (감가상각 단위 = 이미지)
  body: 니트 소매, 무릎 위 옷자락   # 얼굴 없음
  persona_tokens: [연한 색 네일, 파란 키링, 크림 톤 옷]   # 페르소나 카드에서 딱 3개
  props: [아이스 음료 한 잔]        # 1~2개, 장소를 설명하는 것만
```

### ⓑ 화면 블록 — 화면에 그려질 문자열만
대괄호 라벨·색 이름·컴포넌트 이름·칸 수·주석은 넣지 않는다 (run-02 `[예정] 일정`, run-03 `· 파랑` 유출 사고). **문자열은 전체를 쓴다** — 말줄임은 렌더의 일이다 (run-02). 형식은 §2.

### ⓒ 슬롯 배정 + 계산 근거 — 프롬프트에 들어가지 않는다
어느 항목이 템플릿의 어느 자리(슬롯)에 들어갔는지, `+N`·정렬·요일 계산. **색은 여기서만 다룬다**: 슬롯은 템플릿 명세에 색이 정해져 있으니 "같은 종류의 일정 → 같은 색 슬롯"으로 배정한다. 프롬프트에는 색 얘기가 한 마디도 안 들어간다.

## 2. 컴포넌트 사전 — 블록 모양과 채우는 규칙

앱이 실제로 렌더하는 문자열만 쓴다 (`FACTS.md` §0 — 제품은 사실). 앱 문자열(ko.lproj): 헤더는 사용자 편집 필드(이 계정 `일정` / `할 일`) · 시각 `h:mmAM/PM` · 종일 `하루 종일` · 구분선 `내일` / `모레` · 마감 지남 `• 마감일 지남`(미완료 할일만) · 4분면 `중요 & 긴급` / `중요 & 여유` / `긴급 & 덜중요` / `여유 & 덜중요`.

### 2-1. 예정 리스트 (T2)
```
일정   +2
티켓 예매
하루 종일
출근
8:20AM
내일
라팍 홈3연전
9/8~10
유니폼 수령
하루 종일
```
- **구분선은 템플릿이 들고 있다.** 블록에는 라벨 `내일`만 쓴다 — `── 내일 ──`처럼 쓰면 대시가 글자로 그려진다 (run-04~07 사고, 팀 피드백 2026-09-08).
- 데이터: 주간 일정 중 D+0·D+1. 명세의 `today_slots`·`tomorrow_slots`만큼.
- **정렬 (앱 코드)**: 마감 지남 할일 → 하루 종일·진행 중 → 시각 있는 것(시각순) → 날짜만 → 미래.
- `+N` = 오늘~모레 항목 총수 − 보이는 수. 0이면 생략. 여러 날은 `9/8~10`. 시각은 24h 입력을 `h:mmAM`으로 변환.
- 막대 색: 명세의 슬롯 색. 같은 종류끼리 같은 색 슬롯에 (ⓒ).

### 2-2. 할 일 리스트 (T2)
```
할 일   +1
○ 라팍 주차 정기권 연장 신청
○ …
```
- 명세의 `task_slots`만큼, 전체 제목 그대로. `+N` = 총수 − 보이는 수. 기한 지남은 선택(배치당 최대 1, 아래 줄 `9/5 • 마감일 지남`).

### 2-3. 주간 띠 (T3) — 슬롯 매핑
앱 동작: 7열은 **달력 주(일~토)**, 설정 `this_week` / `next_week`(명세 `week_range`). 오늘 밑줄.
**자유 배치 금지 (run-03: 열 정렬 오류 3건).** 명세 `band_slots`에 템플릿 막대의 (행, 열 범위, 색)이 적혀 있다. 주문서는 **그 범위에 맞는 항목을 골라 슬롯에 넣는다** — 3일 슬롯엔 3일짜리, 1일 슬롯엔 1일짜리. 맞는 항목이 없으면 슬롯을 비운다(블록에서 그 막대 문자열을 생략하면 검수가 "빈 슬롯"으로 대조한다). 넘치는 날짜는 `+N`.
```
일 월 화 수 목 금 토
6 7 8 9 10 11 12
(1행) 티켓 예매 | 라팍 홈3연전 | 팀 회식 | 부모님 집
(2행) 출근 | 유니폼 수령 | 네일 | 동성로 팝업
(3행) 필라테스 | 필라테스 | 브런치
+1 (금)  +2 (토)
```
블록에는 제목만. 열 범위는 ⓒ에.
- **기기 날짜 권고**: `this_week`면 일~화, `next_week`면 목~토. 토요일에 `this_week`면 D+1~6이 안 보인다.
- 제목 4~8자(띠 폭).

### 2-4. 4분면 (T3)
```
중요 & 긴급 (7)        중요 & 여유 (7)
• 청첩장 답장 보내기    • 연말 서울 원정 숙소 알아보기
+3                     +3
긴급 & 덜중요 (5)      여유 & 덜중요 (5)
• …
```
- 할일에 **중요/긴급 태그** 필요 — 입력에 있으면 그대로, 없으면 주문서 단계에서 페르소나 기준으로 붙이고 근거를 ⓒ에.
- **18개 이상 필요**(4+4+5+5 + 숨김). 배지 = 분면 총수, `+N` = 총수 − 보이는 수.

### 2-5. 시계·날짜 (전 템플릿)
iOS가 그린다. KR `9월 8일 화요일` / JP `9月8日 火曜日` / TW `9月8日 星期二`. 시계 `7:38`. **요일은 실제 달력으로 검증.** 시계 굵기·색은 iOS 잠금화면 기능이라 컨셉 팩이 정한다(§3).

### 2-6. 월간 그리드 (T1) — 미완. 한 달치 일정 30~40개, 날짜 아래 표기(JP 六曜는 일본 전용, KR 음력 스위치) 필요.
### 2-7. D-day 카드 (T1) — 미완. 페르소나 기념일 2개(카운트다운·경과일) 필요.

팩이 비어 있으면: `font: 시스템 기본`, `clock_weight: 보통`, 나머지 `[열린 칸]`으로 표기하고 지어내지 않는다.

배경에 대해 항상 지키는 것
- 모티프는 **글자를 피해 여백을 채운다** (시계 옆·모서리·하단). 글자 뒤는 비운다.
- **모티프는 또렷하게** — 외곽선이 살아 있고 채도 높은 평면 채색. 흐리거나 반투명·수채풍으로 만들지 않는다. 크게 몇 개를 글자 없는 구역에, 작은 장식은 적게. 근거는 취향이 아니라 **피드 썸네일 판독**(손가락 두 개 폭에서 희미한 모티프는 사라진다)과 캐릭터 인지 속도 — 그래서 컨셉 불문 기본값으로 두되 **가설** 지위(run-04 final-v2가 반투명 파스텔로 나와 레퍼런스와 어긋남, 2026-09-08). 스타일 지시가 없으면 모델은 겹침을 피하려고 흐리게 간다.
- 실존 인물 얼굴은 만들지 않는다. 캐릭터명·팀명은 허용. 직업 소품·작업 공간·워터마크·로고 카탈로그 금지 (`PERSONA.md` 취향 원칙).
- 폰트·시계 굵기는 앱(TTF/OTF 커스텀 폰트 가져오기, 셀별 오버라이드)과 iOS(시계 굵기·색)가 실제로 허용하는 범위다 — 진실성 문제 없음.
- 배경 레퍼런스 이미지는 쓰지 않는다(§7 실험 항목). 실사 피사체가 꼭 필요하면 v0.2의 별도 생성 경로를 옵션으로 쓴다.

## 4. 프롬프트 — 세 개가 전부다

폰트 크기·간격·칸 수·색 이름·배터리·컴포넌트 이름은 넣지 않는다. 프롬프트에 적힌 문자열은 **화면에 그려진다** (run-01 `배터리 80`, run-02 `[예정]`, run-03 `· 파랑`).

**A. 텍스트 교체** (입력 1장: `template.png`)
```
이 잠금화면의 글자 내용만 아래대로 바꿔라. 날짜·시계·헤더·구분선 라벨·시각 표기까지
전부 아래에 적힌 그대로. 아래에 없는 글자는 남기지 마라 — 특히 다른 언어 글자.
일정·할 일 글자의 글꼴은 {style.font}으로 바꾸되, 글자 모양만 바꾸고 각 줄의 위치·행 간격·글자 크기는 그대로 둔다.
시계와 날짜는 iOS 기본 글꼴 그대로.
컴포넌트는 절대 건드리지 마라 — 구분선의 형태와 위치, 색 막대의 위치와 굵기, 아이콘, 헤더 배치,
상태바, 하단 버튼, 두 열의 정렬, 배경.

{date_line} / {clock}

{화면 블록 ⓑ}
```

**B. 배경 채우기** (입력 1장: `text.png`)
```
이 잠금화면의 흰 배경을 {motif} 배경화면으로 채워라 ({concept} 컨셉).
일정·날짜·시계 컴포넌트와 글자에 겹치지 않게, 글자가 없는 여백 — 시계 옆,

글자·글꼴·레이아웃·아이콘·색 막대·상태바·하단 버튼은 그대로.
```

**C. 씬 생성** (생성. `final.png`을 레퍼런스로 첨부. 세로 3:4)
```
첨부한 잠금화면이 켜진 아이폰을 한 손에 들고, 위에서 내려다보며 찍은 사진.
폰은 프레임의 30~50%, 살짝 기울어져 있다. {scene.body}가 자연스럽게 프레임에 들어온다. 얼굴은 없다.
{persona_tokens[0]}을 한 손. 투명 케이스에 {persona_tokens[1]}. 옆에 {scene.props}.
밝고 정돈된 배경 — {scene.place}. 한쪽에서 들어오는 자연광과 부드러운 그림자.
```

### 4-L. 완성 잠금화면의 국가별 글자 교체

입력 1장: 대표 국가의 선택된 `final.png` 또는 `final-v2.png`. 대상 국가 주문서는 대표와 같은 항목 ID·슬롯 순서를 사용한다. 번역 때문에 항목을 다른 슬롯으로 옮기지 않는다.

```text
이 완성된 잠금화면의 화면 글자만 아래 내용으로 교체해라.
날짜·시계·헤더·내일 라벨·일정·할일·시각 표기는 아래 그대로. 아래에 없는 기존 화면 글자는 남기지 마라.
배경 그림·캐릭터·장식의 모양과 위치·색·밀도, 시계의 색과 굵기, 글꼴 느낌, 레이아웃·행 간격·색 막대·아이콘·상태바·하단 버튼은 그대로 보존해라.
전체 제목을 입력하되 칸을 넘는 제목은 기존처럼 말줄임 처리해라. 행을 늘리거나 글자 크기를 일괄 축소하지 마라.

{date_line} / {clock}

{화면 블록 ⓑ}
```

검수 L: 대상 주문서와 문자열 대조 / 원본 언어 잔상 / 긴 제목 판독성 / 슬롯·색·배치 / 배경 디자인 보존 / 날짜·시각·+N.
JP·TW 공통 한자와 AM/PM·브랜드명은 단순 문자종류로 반려하지 않고 확정 문자열과 비교한다. 장식 안 글자는 번역 대상이 아니다.
기하 스크립트는 L에도 사용하지 않는다(완성 배경 오검출). 원본과 직접 시각 비교한다.
보존은 **육안 디자인 동일성**과 **픽셀 동일성**을 구분해 기록한다. 픽셀을 검사하지 않았다면 미측정으로 쓴다. 유사한 그림으로 다시 그려졌으면 동일 디자인 통과로 처리하지 않는다.
반려면 위반한 검수 문장만 덧붙여 **같은 대표 원본에서 1회 재시도**한다. 첫 결과는 덮어쓰지 않는다.

## 5. 검수 — A·B·C 및 국가별 편집 L

**검수 A — `text.png` (텍스트 확정)**

| ⑩ | 재시도 시 폰 각도와 화면 각도가 더 맞는 쪽을 고른다 | 반려 사유 아님 |

각 단계는 `context/templates/review-stage.md` 형식으로 모든 해당 항목의 판정과 관찰을 기록한다. C의 ①~⑨는 각각 기록하고 ⑩은 관찰/해당 없음이다. “core checks 통과” 한 줄로 전체 통과를 대신하지 않는다.
추가 접시·노트·인형은 ④의 소품/요소 수에 포함하고, 표면 글자는 ⑦의 허용 범위·깨짐 여부로 판단한다. UI 글자가 아니라는 이유만으로 자동 면제하지 않는다. 항목을 확인할 수 없으면 미확인으로 표시하고 사용자 확인 대상으로 남긴다.

팀 불변 3항목(잠금화면으로 믿김 / 일정 판독 가능 / 생활감)은 사람이 본다.

## 6. 기록
`템플릿 id · 주문서 · 이 문서 version · 모델 · 단계별 이미지(text*, final*, scene*) · 프롬프트(재시도 포함) · 검수 A/B · 사람 판정`. 반려본은 버리지 않는다 — 문서 고칠 때 같은 입력으로 다시 돌리는 회귀 세트.
