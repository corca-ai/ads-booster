# 최소 실행 규칙

이 문서는 콘텐츠 성과 가설이 아니라 시작·선택·저장·재개 절차다. 자동형 우선이라는 사용자 목표에 따라 아래 기본안을 사용한다. 성과 최적화로 검증된 규칙이 아니며 사용자가 선택 방식을 바꾸면 다음 런부터 갱신한다.

## 확정된 흐름

1. `/trace-post 귀여움` 또는 자연어로 카드 선택. 인자 없으면 카드 목록 제시. 여러 카드가 일치하면 하나를 고르게 한다.
2. 카드 1개와 국가 블록을 한 런으로 처리. 귀여움 현재 국가는 KR·JP·TW. T2부터 지원하며 T1/T3 요청은 입력 계약 미지원이라고 설명한다.
3. 카드·템플릿·모티프·장소·캡션 뼈대·국가·대표 국가·기기 날짜를 run.json에 기록. 명시적 템플릿/모티프 오버라이드는 카드/지원 범위 안에서 적용.
4. 실제 실행 날짜를 기기 기준일로 하고 해당 월~일 일정 생성. 특정 날짜 요청이 있으면 그 날짜 사용.
5. 생성 실행자는 현재 요청의 명시 모델·reasoning effort를 우선하고, 미지정 시 Luna medium을 비용 기본값으로 쓴다. package.json → localization.json → 조립기 → 주문서/프롬프트 → 대표 A/B → 타국 L → 국가별 C → 검수/POST.md.
6. 대표 국가 KR. KR이 없는 다른 카드의 대표 선택은 스킬 구현 시 명시해야 하며 무단 추정하지 않는다. 이번 귀여움 카드의 확정 범위는 KR·JP·TW다.
7. 자동형은 내부 검수 통과 시 다음 단계 진행. 관여형은 같은 절차에서 캡션/현지화 결과와 잠금화면 결과 사이에 사용자 확인을 둔다. 첫 구현은 자동형.
8. 실패는 단계별 최대 1회 품질 재시도. 중단·도구 오류는 품질 반려와 따로 기록. 완료 출력 확인 후 재개하며 이미지를 불필요하게 재생성하지 않는다.
9. 최종 산출물은 캡션·잠금화면·씬·검수 요약. 링크·튜토리얼 열린 칸은 그대로 표시. 게시/커밋/푸시는 별도 사용자 지시가 있을 때만.

## 자동 선택 기본안

- 모티프·장소: 카드 목록 안에서 직전 완료 런과 같은 값을 피한다. 후보가 하나면 그대로 사용하고 반복임을 표시한다. 카드 배열 순서로 남은 후보를 고르면 동일 입력·이력에서 선택을 재현할 수 있다. 이 순서는 성과 최적화 주장이 아니다.
- 캡션: 준비된 문장과 사용 조건을 만족하는 뼈대만 후보로 삼는다. 밈은 현재 유행 근거, 발견담은 계정 사용 맥락과 저빈도 조건을 확인한다. 이력을 모르면 알고 있다고 가정하지 않는다.
- 현재 자동 문장 조립이 준비된 것은 recommend다. 밈/발견담의 자동 전환 주기(예: 5회마다)는 확정하지 않는다. 무조건 번갈아 쓰는 규칙도 만들지 않는다.
- recommend 연속 사용은 현행 CAPTION-RULES상 주의 사항이며 자동 금지 조건이 아니다. 이전 생성과 반복이면 기록하되 게시 이력을 추정하지 않는다. 밈/발견담의 사용 조건을 확인할 수 없으면 후보에서 제외한다. 준비된 후보가 전혀 없을 때만 그 선택을 짧게 확인한다. 생성 완료 이력은 게시 완료 이력과 다르다.
- 사용자가 관여형을 고르면 생성 시작 전에 모티프·장소·뼈대를 짧게 확인한다.

## 저장·이력

`output/posts/YYYY-MM-DD-<concept-slug>-NN/`에 저장. 같은 날 반복 실행하면 새 번호, 재개 요청은 기존 폴더 사용. 폴더 존재 여부로 게시 완료를 추정하지 않는다. run.json 선택값과 단계 상태만 생성 이력으로 읽고 과거 채팅/이미지 전체는 다시 로드하지 않는다.

## 이번 흐름의 예

“귀여움으로 만들어줘” → cute 카드 찾기 → 직전 미피·카페를 피한 카드 내 모티프/장소 선택 → 준비된 캡션 뼈대 선택 → 오늘 날짜 run.json 저장 → 공통 일정·3국 번역 → 새 대표 배경 → 국가별 글자 편집 → 같은 씬 프롬프트 → 결과 표시.

이 예의 다음 모티프/장소/뼈대 값은 아직 실제 런 선택이나 생성 지시가 아니다.
