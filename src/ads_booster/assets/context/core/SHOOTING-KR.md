# Trace 촬영 상시 컨텍스트 (KR)

> 촬영 에이전트가 매 촬영마다 전문으로 읽는 상시 주입 파일. `context/README.md` §3 참조 — 촬영 단계는 원리 원문을 다시 읽지 않고 아래 확정 규칙만 실행한다. FACTS.md와 함께 읽는다.

## A. 확정 규칙 (근거 병기)

**① 정합 원칙.** 화면 속 모든 디테일(일정 문구·기기 시각·배경화면·배터리)이 캡션 속 인물과 정합해야 한다. 배경화면은 "개인 취향" 같은 모호어로 지정하지 않는다 — 반드시 페르소나로 지정한다. 예: 직장인 화자 → 가족사진류/미니멀 데스크탑, 야구부 화자 → 구단 관련 이미지. 촬영 주문서의 배경화면 필드는 `{background_subject: character_kitty | family_photo | minimal | sports_team | ..., mood: "..."}` 형태로 명시한다(`context/README.md` §5-1 출력 스키마 참조).
- 근거: 2026-08-24 팀·사용자 결정. PRINCIPLES-KR 이미지원리 A(잠금화면 데모는 도메인 정합이 반응을 만든다)의 확장.
- 정합 실패 경고 사례: kr-016은 캡션(집안일 이름표 에피소드)과 이미지(스토어 검색순위 캡처)가 서로 다른 게시물에서 온 불일치가 드러나 정량 근거로 폐기됐다(`research/stage3-korea.md` §1). 정합이 깨지면 레코드 전체가 무효화된다.

**② 이미지는 실사용 증거다 — 카탈로그·설정 화면 금지.** 앱 UI 크롬(네비바·탭바) 노출 금지, 잠금화면/홈화면 그대로 노출한다.
- 근거: PRINCIPLES-KR 원리 11 — `first_cut_role: product_showcase` 유일 사례 kr-006(rel 0.02)이 최하위. PRINCIPLES-TW 원리 8 — tw-012는 완성된 위젯이 아니라 iOS "위젯 추가" 설정 메뉴만 캡처해 rel 0.021, 같은 계정 자기소개 게시물(rel 0.306)의 **1/15**.

**③ 정지 스크린샷보다 세로 영상을 우선한다.** 반드시 실기기 화면 녹화, 자동재생 세로형으로 촬영한다.
- 근거: PRINCIPLES-KR 원리 13 — 시각 히트 5건 중 4건이 자동재생 세로 영상이고, 상위 2건(kr-027 rel 2.16, kr-026 rel 0.82)이 모두 영상.

**④ 입력_일정은 워커가 캘린더에 먼저 쓰고, 촬영은 그 캘린더를 지정만 한다.** 촬영 주문서의 `trace_items` 필드는 페르소나 카드 → LLM이 생성한 **주간 일정 객체 18~22개**다(제목·요일 오프셋·기간·시각·색, 현지어·계절 정합). 워커가 요청 전용 iOS 캘린더에 전부 기록한 뒤 촬영이 시작되며, Appium은 일정을 타이핑하지 않고 컴포넌트에 그 캘린더를 지정한다. "일정 1~2개만 넣어라" 식의 모호 지시는 금지 — 페르소나의 정체성이 캡션이 아니라 화면 속 일정 문구로 드러나기 때문이다. 화면에 다 안 보이는 일정은 "+N" 배지로 접히며 그것이 정상이다.
- 근거: 2026-08-24 팀·사용자 결정 (페르소나→일정 생성 파이프라인), 2026-09-01 주간 일정 계약 전환(중복 생성 제거).

**⑤ 상태바·배터리·시각은 자연스럽게 둔다.** 배터리 잔량 극단치(1%, 100%)나 페르소나 생활 시간대와 안 맞는 시각(예: 야간 근무 없는 페르소나의 새벽 4시 알림)을 피한다.
- 근거: 정합 원칙(①)의 하위 적용.

**⑥ 앱명 노출은 촬영 주문서의 게이트 전략을 따른다.** 게이트(캡션 은닉+댓글 회신) / 프로필 유도 / 공개 중 촬영 주문서에 명시된 지시를 그대로 따르고 촬영 단계에서 임의 판단하지 않는다.
- 근거: FACTS.md #12 (앱명 노출 정책 — 팀 확정 대기, cand-02 vs cand-05 전략 통일 필요).

## B. 공백 질문 ([주원확인]/[팀확인] — 지어내지 말 것)
